# Frontend — As-Built Reference (Dev 1)

> **Status: BUILT.** This replaces the original 6-task plan (landing/login/signup/
> upload/SSE-results/dashboard). The frontend was built richer than the plan and
> then reconciled to the **implemented** backend, which pivoted to an
> obligation-centric model. This document describes **what actually exists** so a
> coding agent can run, understand, and extend it.

## What changed vs the original plan

| Original plan | As built | Why |
|---------------|----------|-----|
| Auth: `/login`, `/signup`, JWT in localStorage | **No auth** | Implemented backend has no auth (user optional) |
| SSE streaming `/results/[id]` | **Synchronous** upload → letter detail | Backend `POST /letters` returns the full extraction in one response |
| `/dashboard` table | **`/deadlines`** iPhone-style calendar + agenda, **`/letters`** home, **`/documents`** | Obligation-centric UX |
| Response-letter draft, checklist, citations sections | **Obligations** (`actions[]`) + steps + evidence + RAG chat | Backend extracts actions, not drafts |
| Deep-blue palette, system fonts, CSS modules | **Editorial paper/ink + electric lime**, Clash Display / General Sans / Space Mono, **Tailwind v4** | Distinctive brand (see `01-frontend.md` §design) |
| `next-pwa` | **Serwist** (`@serwist/next`) | Modern SW tooling |
| `frontend/src/app/...` | App at **repo root** (`app/`, `components/`, `lib/`) | Single Next app at root |

> Note: `CLAUDE.md`'s repo-structure snippet still shows `frontend/src/app/…`; the
> actual app lives at the **repository root**. (Left as-is per scope: frontend-only.)

## Stack

- **Next.js 15** (App Router) · **React 19** · **TypeScript strict**
- **Tailwind CSS v4** (CSS-first `@theme`; design tokens as CSS variables)
- **motion** (`motion/react`) for animation

`npm run typecheck`.

## Data layer & backend integration

All network access goes through `lib/api/client.ts`. It reads
`NEXT_PUBLIC_API_URL` and talks to the backend's root routers (`/letters`,
`/actions`, `/rag`, `/health`) — **no `/api` prefix, no auth**. Content endpoints
carry the user's language as `?lang=`. The full request/response contract is in
**`docs/06-frontend-integration-contract.md`** — that is the source of truth.

- `lib/hooks.ts` — `useLetter(id)`, `useActions(status?)`, `useLetters()`. They
  depend on the current language, so switching language re-fetches localized data.
  `useLetters()` builds the home/documents feed from `/actions` + per-letter
  `GET /letters/{id}` (the backend has no list-letters endpoint) and falls back to
  the store's offline cache.
- `lib/adapt.ts` — maps backend data to display: `deadline` → urgency + countdown,
  `category` → icon + label, `severity` → label/colour, "handled" = all actions
  done/ignored.
- `lib/store` — persists `lang`, `theme`, `onboarded`, and a **letters cache**
  (for the feed + offline). `pendingUpload` (a `File`) is staged by `/scan` and
  consumed by `/scan/processing` (not persisted).

### Mock mode

With `NEXT_PUBLIC_API_MODE=mock`, MSW (`lib/api/mocks/`) intercepts the exact same
requests and serves seven seeded letters + a mocked extraction on upload, and
**localizes content** by `?lang=` (German + Persian provided in
`content-i18n.ts`). This keeps the demo clickable and lets the backend be built in
parallel. Switch to `live` and point `NEXT_PUBLIC_API_URL` at the backend — no
code changes.

## Design system (summary)

Editorial, document-led, paper + ink with one electric-lime accent. Tokens live
as CSS variables in `app/globals.css` and are exposed through Tailwind (`bg-bg`,
`text-ink`, `bg-brand`, urgency colours…). Dark mode via `data-theme`. Four brand
devices: the **KLAR stamp** (`components/brand/Stamp`), the **highlighter sweep**
(`HighlightText`), **fog-to-clear** (`OriginalLetter`, `ReadingLoader`), and the
reimagined-officialdom document styling. Motion signatures are gated behind
`prefers-reduced-motion`. Full details in `docs/01-frontend.md`.

## Responsive & PWA

- **Desktop:** left sidebar rail + wide content (detail and calendar go
  two-column). **Mobile:** fixed bottom tab bar (4 tabs + center lime scan FAB) +
  slim top bar. Same screens, two layouts.
- **PWA:** `app/manifest.ts` (standalone, KLAR-stamp icons incl. maskable);
  `sw.ts` (Serwist) — network-first for `GET`s to `/letters`,`/actions`,`/rag`,
  `/health`; cache-first fonts; SWR images; `/offline` navigation fallback.
  Registered in production/live only (never shares scope with the MSW worker).

---

## i18n / RTL

`lib/i18n` holds per-language dictionaries (en/de/fa populated; tr/ar/uk fall back
to en) and a `dir` map that sets `rtl` for Persian/Arabic on `<html>`. UI uses CSS
logical properties throughout. **Letter content** is localized by the backend via
`?lang=` (emulated in mock); UI chrome is localized via the dictionaries.
